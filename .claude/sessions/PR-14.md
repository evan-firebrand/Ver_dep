## Discoveries

- **`searchParams` is a Promise in Next.js 16, same as `params`.** Both must be `await`ed
  before destructuring. The acts listing uses `searchParams: Promise<{ genre?: string }>`
  for server-side genre filtering. Same pattern as `params: Promise<{ id: string }>` in
  dynamic routes.

- **Genre filter validation before casting.** `ALL_GENRES.includes(genreParam as Genre)`
  safely validates an untyped URL query string value into the `Genre` union without an
  extra library. Unknown values fall through to `null` (no filter), which is the correct
  fallback.

- **Notion date strings sort correctly with plain string comparison.** Both `'2026-04-14'`
  (date-only) and `'2026-04-14T20:00:00.000-05:00'` (datetime) sort lexicographically in
  the expected order, so `date.start >= today` correctly filters upcoming events for both
  formats.

- **The search stub also needs `await connection()`.** It was an async page component
  reading `searchParams` without Suspense. The build caught this the same way it caught
  the acts pages — "Uncached data accessed outside of `<Suspense>`". The fix is identical:
  sync outer page → `<Suspense>` → async inner component with `await connection()`.

## Future Agent Advice

- The genre filter on `/acts` is purely server-side (URL-driven). Clicking a genre link
  navigates to `/acts?genre=Jazz`, which the server reads and filters on. A client
  component with `useRouter` would be needed for instant/debounced filtering.
- On the act detail page, "upcoming" means `date.start >= today` at server render time.
  Past performances are silently excluded. Flip the filter and reverse the sort to add a
  past-performances section.
- `actTypeColors` in `ActCard.tsx` is a complete `Record<ActType, string>`. Adding a new
  `ActType` value to `types.ts` will cause a TypeScript compile error on that record —
  intentional, the compiler tells you to add the color.
- When implementing `/search`, read the TODO comment in `src/app/search/page.tsx` for the
  recommended approach and edge cases. `SearchResult`, `SearchResultKind`, and
  `SearchResults` types are already defined there.
