# Session Notes — PR #30: UX overhaul (dynamic home, /events filters, cross-linking)

## Date

2026-04-22

## Discoveries

- **Next 16 Cache Components forbid dynamic APIs outside `<Suspense>` at prerender.** Client components that call `usePathname()`, `useRouter()`, or `useSearchParams()` inside the root layout or any prerendered page will fail `npm run build` with "Uncached data was accessed outside of `<Suspense>`". This doesn't surface in `lint`, `typecheck`, or `vitest` — only at `next build` time. `next dev` is also more forgiving. Run `npm run build` before pushing, not just the other four checks.

- **Fix pattern for dynamic client islands:** split into a server shell that renders static chrome + a Suspense-wrapped client island with a server-renderable fallback. See `src/components/Nav.tsx` (shell) + `src/components/NavLinks.tsx` (client island with `NavLinks` + `NavLinksFallback` export). The fallback must not call any dynamic hooks — it renders the same DOM shape without the dynamic piece (no active-state styling in the Nav case).

- **Simpler fix when the client island has no fallback content:** wrap in `<Suspense fallback={null}>` and accept a momentary absence. Used for `FilterBarUrl` on `/events` (`src/app/events/page.tsx:42-46`).

- **Async Server Components can't be unit-tested with Vitest + RTL.** CLAUDE.md rule 6 already says this, but the practical consequence: when a previously-sync page becomes async + fetches Supabase (like home did in this PR), the test file has to be rewritten to cover only the synchronous shell. Don't try to work around it by mocking Supabase inside the test — CLAUDE.md explicitly reserves this for future Playwright coverage.

- **`src/lib/format-date.ts` had a subtle TZ bug.** It used `toLocaleDateString()` / `toLocaleString()`, which rely on the host's system timezone. Date-only events rendered with the correct day (local midnight interpretation), but datetime events on a host outside NOLA would render the wrong local time. The canonical `src/lib/events/formatters.ts` uses `Intl.DateTimeFormat` with `timeZone: 'America/Chicago'` explicitly. If you see a new `formatEventDate` utility appear in the codebase, merge it into `formatters.ts` — don't accept a second copy.

- **`Intl.DateTimeFormat('en-CA', { timeZone: 'America/Chicago' })` produces `YYYY-MM-DD`.** Useful shortcut for deriving "today in NOLA" regardless of host TZ. Used in `/this-week`, `/events`, `/acts`, and `/` pages.

## Dead Ends

- **Tried wrapping the whole Nav in `<Suspense fallback={null}>` in `layout.tsx`.** This works but flashes empty chrome during hydration. The server-shell + client-island pattern is strictly better — the logo, borders, and all link shapes render immediately; only the active-state highlight appears after hydration.

- **Considered using repeated-key searchParams (`?type=Festival&type=Brass`) for multi-value filters.** Next.js returns those as `string | string[] | undefined`, requiring an `Array.isArray` branch at every parse site. Went with CSV (`?type=Festival,Brass`) instead for simpler handling and more readable URLs. The adapter in `src/lib/events/search-params.ts` still guards against array-valued params (by taking `firstString`) in case someone manually constructs one.

## Codebase Gotchas

- **Two flavors of EventCard existed** (`src/components/EventCard.tsx` and `src/components/this-week/EventCard.tsx`) with different props, different theming, and different link behavior. Only the first linked to `/events/[id]`; the this-week one didn't. This was a UX dead-end and a maintenance trap. Now unified into one component using the richer this-week render with title-as-link pattern. If you find yourself adding a variant, argue hard against it — use a prop instead.

- **Card link pattern is title-as-link, not whole-card-link.** `<article>` is a plain container; `<h3>` contains the `<Link>`. Badges are siblings at the same level and render as their own `<Link>`s (filter links into `/events?…`). This avoids nested interactive elements. If you add new interactive things to a card, add them as siblings — do NOT re-wrap the article in a `<Link>`.

- **`/events` page needs both a `venueById: Map` and a `venueMap: Record<string, Venue>`.** `applyFilters()` takes the `Record` shape (for `filterByNeighborhood`'s venue lookup), while the card rendering path uses `Map.get`. They're built from the same venues array — kept side by side in `EventsList`.

- **Runtime-side arrays for unions live in `src/lib/events/search-params.ts`.** `EVENT_TYPES` and `NEIGHBORHOODS` are `readonly` arrays matching the TypeScript unions. If you add a new `EventType` in `src/lib/supabase/types.ts`, remember to also add it to `EVENT_TYPES`. Same for `Neighborhood` + `NEIGHBORHOODS`. No compile-time enforcement of the sync — worth an ADR eventually.

- **`this-week/FilterBar.tsx` and `events/FilterBarUrl.tsx` have duplicated markup (~30 lines).** They're intentionally not extracted — the state models diverge (callback-driven vs URL-driven). Don't force a shared component unless you see a third call site.

- **Date bucket rule interacts subtly with the home page's "weekend" computation.** `src/lib/events/bucket-by-date.ts` groups events for `/events`. `src/app/page.tsx:118-127` computes weekend events independently for the home "This Weekend" section. The rules are close but not identical (home only scans `i=2..7` so it can't include today/tomorrow as weekend). If you change bucketing semantics, search for `weekendEvents` in page.tsx too.

## Future Agent Advice

- **If you add or move any source file, update `CODEBASE.md`.** The map is dense and surprisingly useful when starting cold — keep it in sync or it decays fast.

- **Before reaching for a new shared helper, check `src/lib/events/` and `src/lib/acts/`.** The filters, formatters, search-params adapter, and bucket helper are already composable; most "I need to group/sort/filter events" tasks can reuse these.

- **Run `npm run build` (not just `test`) before pushing.** Cache Components errors only show at build. The five-command pre-push checklist in CLAUDE.md is authoritative.

- **Home page is dynamic now.** Any change to `src/app/page.tsx` that touches the `UpcomingSections` async inner component must preserve `await connection()`; removing it re-enables prerender and the Supabase calls will either cache-bust the build or fail silently. Test files cover the synchronous shell only.

- **The `/search` stub was deleted** (not left as TODO). If search returns, it's a new feature — no legacy code to honor. Types and skeleton are in git history if needed.

- **Visual identity refresh is the planned follow-up.** Don't ship typography/palette/logo changes in unrelated PRs — they belong in a dedicated plan so the design choices can be reviewed together.
