# Session Notes — PR #12: NOLA Music Tracker pages

## Date

2026-04-13

## Discoveries

- **`next/font/google` fails in network-restricted build environments (e.g. the local dev container).** Google Fonts is fetched once at build time and cached; if the build environment can't reach `fonts.googleapis.com`, the build fails with a hard error (not a warning). The fix is `next/font/local` pointing at local woff2 files. Geist Latin subset woff2 files are bundled inside Next.js itself at `node_modules/next/dist/next-devtools/server/font/geist-latin.woff2` and `geist-mono-latin.woff2`. These are identical to what `next/font/google` would download.

- **RTL auto-cleanup silently breaks in this Vitest setup.** `@testing-library/react` registers cleanup via `if (typeof afterEach === 'function') afterEach(cleanup)`. In Vitest without `globals: true`, `afterEach` is NOT a global — it must be imported. So RTL's check is `false`, cleanup never fires, and tests accumulate DOM nodes across test cases. This causes `getByRole` (strict, throws on multiple matches) to fail starting from the second test in any file that uses `render()`. The existing `page.test.tsx` was written with `getAllByRole` and `hrefs.some(...)` precisely to work around this, but any new DOM tests using `getByRole` will fail. Fix: add `afterEach(cleanup)` to `src/test-setup.ts`.

- **Next.js 16 `params` in dynamic routes is a Promise.** `params: Promise<{ id: string }>` — must `await params` before destructuring. The docs example at `node_modules/next/dist/docs/01-app/01-getting-started/06-fetching-data.md` confirms this pattern.

- **Notion IDs are valid URL slugs.** Notion page IDs (`10a698eb-000e-4b66-943a-c85a776b0763`) use dashes and are URL-safe. Routes like `/events/10a698eb-000e-4b66-943a-c85a776b0763` work without any encoding.

## Dead Ends

- **Tried `unstable_cache` from `next/cache` for cross-request caching.** Next.js 16 has migrated to the `use cache` directive (requires `cacheComponents: true` in `next.config.ts`). `unstable_cache` still exists but is on a deprecation path. Decided to defer caching to a separate PR/ADR rather than enable `cacheComponents` without documenting the decision.

## Codebase Gotchas

- **`React.cache()` is per-request only.** Using `const cachedGetEvents = cache(getEvents)` prevents duplicate Notion API calls within a single render tree (e.g., if both the listing page and a child component call `getEvents()`), but does NOT cache across HTTP requests. Each page load hits the Notion API. See ADR-0006 for the production caching requirement.

- **The local font path in `layout.tsx` is relative to the source file.** `../../public/fonts/geist-latin.woff2` works when `layout.tsx` is at `src/app/layout.tsx`. If the file moves, the path breaks. This is a `next/font/local` quirk — paths are resolved relative to the calling file, not the project root.

## Future Agent Advice

- Before adding any tests that use `render()` and `getByRole` (strict single-element queries), verify that cleanup is wired in `src/test-setup.ts`. It is now — but if you see intermittent "Found multiple elements" failures in DOM tests, suspect missing cleanup first.
- If the `geist` npm package ever gets added as a dependency, swap `src/app/layout.tsx` back to `next/font/local` pointing at `geist/font/geist.woff2` (or `next/font/google` if Google Fonts becomes accessible). The current source from Next.js's own devtools bundle is functional but unconventional.
- Cross-request caching for Notion pages is still TODO. Before shipping to production, wrap query functions with the `use cache` directive (and enable `cacheComponents: true` in `next.config.ts`) per the ADR-0006 requirement.
